# سور — Sour

جدار ناري ومكافح فيروسات لويندوز يعتمد على الذكاء الاصطناعي، يعمل كلياً على الجهاز (لا سحابة)، بواجهة عربية/إنجليزية.

## التشغيل

- شغّل `Sour.cmd` (أو `bin\Sour.exe`). يتطلب ‎.NET 9 Desktop Runtime (موجود على هذا الجهاز).
- مكافح الفيروسات والمراقبة يعملان بمستخدم عادي. **فرض قواعد الجدار الناري يتطلب «إعادة التشغيل كمدير»** من داخل البرنامج.
- مفتاح الطوارئ إن انقطع الاتصال بعد تطبيق سياسة: من نافذة أوامر بصلاحية مدير:
  `bin\Sour.exe --fw-off` (يزيل كل مرشّحات سور).

## ما الذي يفعله

| الطبقة | الوصف |
|---|---|
| الجدار الناري | مرشّحات WFP (منصّة التصفية في ويندوز) بمزوّد وطبقة فرعية خاصين. خمسة أوضاع: متوقف، مراقبة، قائمة حظر، قائمة بيضاء (منع افتراضي)، إغلاق تام. تخفٍّ للوارد، حظر عناوين/نطاقات CIDR، قواعد مؤقتة. |
| تثبيت البصمة | قاعدة السماح مرتبطة ببصمة SHA-256 للملف؛ إن تغيّر الملف ولم يكن الموقِّع نفسه عُلّقت القاعدة. |
| الطيار الآلي | لكل برنامج جديد يطلب الشبكة: التوقيع الرقمي + حكم مكافح الفيروسات + موقع الملف ← سماح/حظر/اسأل. |
| ذكاء الشبكة | ملف سلوك لكل برنامج يُتعلَّم محلياً (منافذ، شبكات، ساعات)، وكشف: منفذ نادر، شبكة جديدة، اندفاع، إشارة دورية (Beaconing)، نطاق مولَّد آلياً (DGA). |
| مكافح الفيروسات | قائمة بصمات ← 42 قاعدة توقيع (Aho-Corasick) ← استدلالات بنيوية ← نموذج LightGBM ← رأي ثانٍ من AMSI ← فحص داخل الأرشيفات. كل نقطة في الدرجة مشروحة. |
| الحماية الحيّة | حارس الملفات، حارس العمليات (مع فحص أسطر الأوامر وتجميد العملية الخبيثة)، درع الفدية (ملفات طُعم + كشف إعادة التسمية الجماعية)، حارس USB، مراقبة بدء التشغيل وملف hosts. |
| الحجر الصحي | تشفير AES واستعادة مطابقة بالبصمة. |
| تدقيق الأمان | 18 فحصاً لصلابة النظام (للقراءة فقط)، برامج بدء التشغيل، فحص البرامج الجارية، إضافات المتصفح، الأجهزة على الشبكة، تقرير HTML. |
| أدوات | فحص من قائمة الزر الأيمن، فحص يومي مجدول، إتلاف ملف نهائياً، إجراءات جماعية (حجر/استثناء/استعادة الكل). |

## نموذج الذكاء الاصطناعي (أرقام مقاسة)

- البيانات: EMBER2024 (Win32 + Win64 + ‎.NET)، أول 2500 سجل من كل ملف أسبوعي: 360,000 تدريب، 30,000 تحقق، 90,000 اختبار (أسابيع لاحقة لم يرها النموذج).
- 193 خاصية ساكنة، 1500 شجرة. **AUC الاختبار 0.9967**.
- عند عتبة «خبيث» (0.1% إنذارات كاذبة على التحقق): كشف 85.2% بإنذارات كاذبة 0.18% على الاختبار. مع نطاق «مشبوه»: 94.0% عند 0.95%.
- الاستنتاج في C# يطابق LightGBM تماماً (فرق 0 على 300 عيّنة). مستخرج الخصائص يطابق مستخرج التدريب في 197 من 198 ملفاً حقيقياً.
- قياس الإنذارات الكاذبة على 1500 ملف من `C:\Program Files`: 0 «خبيث»، 3 «مشبوه» (اثنان منها ملفات يؤكد ويندوز أنها عُدِّلت بعد توقيعها).

## التحقق

```
bin\Sour.exe --selftest            99 اختباراً آلياً (كلها تنجح)
python tools\verify_features.py    مطابقة الخصائص مع مستخرج التدريب
bin\Sour.exe --fp-test <dir> <n>   قياس الإنذارات الكاذبة
bin\Sour.exe --amsi-test           فحص مسار AMSI
bin\Sour.exe --snap <dir>          لقطات كل الصفحات باللغتين (docs\shots)
```

## حدود يجب معرفتها

- لا يوجد مشغّل نواة: الملف يُفحص فور كتابته والبرنامج فور تشغيله، لا قبل ذلك.
- لا يفحص محتوى المرور المشفَّر.
- **مسار تثبيت المرشّحات بصلاحية مدير لم يُختبر بعد على جهاز حقيقي** (الجلسة التي بُني فيها بلا صلاحية مدير). ما تم التحقق منه: مطابقة أحجام البنى لترويسات SDK، فتح المحرك، توليد معرّف التطبيق، ومنطق بناء السياسة. جرّبه أولاً في وضع «قائمة الحظر» قبل «القائمة البيضاء».
- أبقِ Microsoft Defender مفعّلاً؛ سور يعمل بجانبه.

للمطوّرين: انظر `DEVELOPER.md` (فتح المشروع، البناء، الاختبار، خريطة الشيفرة).

## البنية

- `src/Sour` — الشيفرة (C# / WPF): `Fw` الجدار الناري، `Av` مكافح الفيروسات، `Ui` الواجهة.
- `ml` — استخراج الخصائص والتدريب (`featspec.py`, `extract_ember.py`, `train.py`).
- `tools/gen_rules.py` — مصدر قواعد التواقيع (يولّد `Data/rules.json` بصيغة معكوسة).
- إعادة البناء: `dotnet build src/Sour -c Release -o bin`
